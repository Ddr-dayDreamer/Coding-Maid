## 现有工具逐个评价

### 1. `bash` — Shell 命令执行

**现状**: `src/tools/bash-handler.ts`，约 200 行，实现较为成熟。

| 维度 | 评价 |
|------|------|
| ✅ 超时控制 | 支持动态超时、SIGKILL 进程树清理、deadline 追踪 |
| ✅ 输出截断 | 30K chars 输出截断 + 10MB 捕获上限，双层保护 |
| ✅ Marker 机制 | 通过专用 marker 精确提取命令结束后的 PWD |
| ✅ Windows 兼容 | 处理了 extglob 禁用、null 重定向转换、原生路径转换 |
| ⚠️ **description 参数未使用** | Schema 中有 `description` 参数，但 handler 中未读取/记录 |
| 🟢 同步模式合理 | LLM 调用工具的天然模型就是串行等待结果，无需异步 |
| 🟢 超时机制足够 | 超时后 SIGKILL 进程树，防止命令卡死 |

> **关于异步执行的说明**: LLM 调用工具是天然串行的（发出 tool call → 等结果 → 继续推理），和 Copilot 的工作方式一致。当前同步模型没有大问题。真正需要「后台进程」的场景（如 dev server、watch 编译）应该通过**跨对话轮次的进程 registry** 来实现，而非 LLM 侧并发。

**改进建议**:
1. **使用 `description` 参数** — 记录到日志或作为 Activity Bar 显示标签（🔴 P0，因为 Schema 已定义但未实现）
2. **进程 registry** — 记录已启动的后台进程 pid/command，跨轮次可查询/终止（🟡 P1，为后续 watch/server 场景准备）
3. **超时可选后台继续** — 超时时不杀进程，允许用户后续手动检查（🟢 P2）

用户指示：检查这个description的情况即可。

### 4. `edit` — 文件编辑

## 🔴 P0 — 必须优先实现

### 1. 代码搜索工具

**现状**: 只能用 `bash` 跑 `rg`/`grep`，不符合"用专用工具而非 shell"的原则。

| 建议工具名 | 功能 | 类比 Copilot 工具 |
|-----------|------|------------------|
| `grep_search` | 正则/关键词全文搜索，支持文件类型过滤 | `grep_search` |
| `file_search` | 按 glob 模式搜索文件路径 | `file_search` |
| `semantic_search` | 自然语言语义搜索，不知道精确关键词时使用 | `semantic_search` |

**理由**: LLM 在大型代码库中导航时，**搜索是最频繁的操作**。没有专用搜索工具，每次都要构造 `rg` 命令然后解析输出，效率低且容易出错。

**实现思路**: 前两个可直接封装 ripgrep 和 Node.js `fs.readdir`/glob，语义搜索可基于简单的 TF-IDF 或调用 LLM embedding。

## 技术实现要点

### 工具注册流程

所有新工具需要在以下位置注册：

1. **`src/tools/`** — 创建 handler 实现文件（如 `grep-handler.ts`）
2. **`src/prompt.ts`** — 在 `getTools()` 中添加 Function Calling Schema 定义
3. **`src/tools/executor.ts`** — 在工具调度器中注册新工具
4. **`templates/tools/`** — 创建对应的 Markdown 使用说明

### 通用工具接口

所有工具 handler 应遵循 `ToolExecutionContext` 接口：

```typescript
type ToolHandler = (
  args: Record<string, unknown>,
  context: ToolExecutionContext
) => Promise<ToolExecutionResult>;
```

### LSP 工具实现参考

`get_errors`、`find_references`、`rename_symbol` 等工具可以通过 VS Code 的 `vscode.languages` API 或直接使用 Language Server Protocol 的请求/响应模式实现。Coding-Maid 作为 VS Code 扩展，可以直接调用 `vscode` 命名空间中的 API。
